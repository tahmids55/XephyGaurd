# Design decisions

| # | Decision | Why |
|---|---|---|
| 1 | Product name **XephyGuard** (spec says "LabGuard"); identifiers `xephyguard-*` | matches the repository/spec file name |
| 2 | **Laravel 13** + Reverb 1.12 instead of Laravel 11 | Laravel 11 is out of security support; `composer audit` showed unpatched advisories (TokenGuard auth bypass, XSS) fixed only in 12/13 |
| 3 | Lab sessions table is `lab_sessions` | `sessions` is Laravel's login-session table |
| 4 | Agent upstream = HTTPS batch POST; downstream commands = Reverb (Pusher protocol) WSS; both via nginx mTLS on :8443 | batches give offline buffering, de-dup by seq, schema validation; Reverb gives push |
| 5 | Agent auth = client cert (nginx-verified, fingerprint matched in PHP) **and** bearer token | a stolen token or cert alone is useless |
| 6 | Signature bundles signed with the CA key and verified by agents (EC P-256 / SHA-256) | integrity of pushed detections; PHP→C++ verification tested |
| 7 | Own minimal TLS/HTTP/WebSocket client on OpenSSL; nlohmann/json, toml++, Catch2 via FetchContent; raw kernel uevents instead of libudev | few runtime deps, small agent (RSS ≈ 15 MB in live test) |
| 8 | All CCC containers use **host networking**; Docker's iptables management disabled | real lab-PC source IPs for per-PC policy; no conflict with nftables |
| 9 | DNS = **Unbound** with per-client views | per-PC policy groups (test / block_ai / isolated / exempt) |
| 10 | SNI blocking in mitmproxy `tls_clienthello` with passthrough (no decryption); interception only for configured search hosts and restricted PCs | minimal decryption |
| 11 | mitmproxy signs with the lab root CA (key stays on the CCC) | intermediate-chain support in mitmproxy unverified; revisit |
| 12 | Windows installer = **NSIS** (`makensis` on Linux) | no Windows runner needed for packaging |
| 13 | Linux process starts: netlink proc connector + 2 s `/proc` diff | catches short-lived processes; works as fallback without root |
| 14 | Common dev ports (5001, 7860, 8000, 8080) need a positive LLM-API probe | false positive found in the live test |
| 15 | A mode change re-evaluates already-running processes, ports, adapters, extensions | live test: a tool opened before the Test was only logged |
| 16 | Scoring lives only in the Python analysis service (v1 rules, v2 IsolationForest opt-in) | single implementation; analysis tests use the real migration schema |
| 17 | Agents use their own API port for the Reverb connection (ignore the server-advertised port) | the CCC cannot see NAT/port-forwarding; found in the container test |
| 18 | When a batch ack announces a new policy version, the agent fetches it immediately | mode switches stay fast even if the realtime channel is down |
| 19 | Analysis SQL backtick-quotes column names (`keys`, `lines`, `usage`, `user`) | MySQL reserved words; SQLite tests could not catch it, found against MySQL 8.4 |
| 20 | mitmproxy runs as dedicated uid/gid 1500 with the CA at its default confdir | unprivileged proxy that can still read the 0600 CA bundle |
| 21 | nginx config uses `listen … ssl http2` (not `http2 on;`) and the image drops Debian's default site | compatible with nginx 1.22 in the Debian-based app image |
| 22 | Agent **actor core**: one core thread owns all agent state; platform watchers, uplink, realtime and workers only post typed messages to a bounded mailbox, and read back immutable snapshots | removes the data-race class behind I-AGENT-7 by construction; core logic is testable by feeding messages (approved by owner 2026-11-17, docs/plan/agent.md) |
| 23 | **Session network lock** in `proxy_only` mode, chosen per session: `observe` drops only QUIC (UDP 443) to public addresses so browsers fall back to TCP through the proxy; `strict` drops every public destination except the CCC (the proxy runs there). Own nft table / firewall rule, separate from Isolate; never applied in gateway mode or Always-on | without a gateway the PAC is only a hint to browsers; observe keeps full browser visibility without restricting the student, strict makes the proxy the only way out (approved by owner 2026-11-17) |
| 24 | **Screen streaming split**: the user-level session helper only captures and encodes; it hands encoded messages to the root service over the existing helper IPC (Unix socket / named pipe). The service opens the gateway WebSocket through nginx on :8443 with its mTLS client cert, reusing the realtime WSS client (no new dependency); nginx verifies the cert, strips any client-sent `X-Agent-Cert-Fingerprint` and passes the verified cert (`X-SSL-Client-Cert`, since nginx has only a SHA-1 fingerprint variable); the gateway hashes it to the SHA-256 fingerprint and trusts these headers only from loopback (owner, 2026-11-17). The service treats helper messages as opaque bytes (type + length check, size cap, never decoded) and starts/stops the helper by a CCC lease. The helper never holds a gateway credential and never connects to the gateway itself | removes the user-readable agent token and the helper's self-start (I-SCREEN-1, I-SCREEN-20); one identity (the mTLS cert) for all agent traffic; makes the per-PC agent JWT and the helper's WinHTTP client unnecessary (approved by owner 2026-11-17, docs/plan/screen.md Phase 0) |
| 25 | **Retire the standalone screen agent `xgagent` (F47)**; `xephyguard-screen/capture` and `core` stay as the one shared capture/encode library used by the embedded streamer (F95) and the benchmark | two programs did the same capture/encode with different bugs; the embedded streamer already links the library (approved by owner 2026-11-17, docs/plan/screen.md Step 43) |
| 26 | **PolicyService** is the one resolver of the agent policy (replaces `PolicyBuilder`). Privacy settings are typed (`PrivacySettings`). The effective `title_capture` is the **stricter** of the profile's `agent.title_capture` and the setting `privacy.title_capture.<mode>`, ordered `off` < `app_only` < `full`; setting defaults: Always-on `off`, Practice/Test `app_only`. The resolved policy is stored per `(pc_id, version)` and invalidated on profile, rule, session, setting and override changes | one source of truth instead of profile and setting silently overriding each other; the stricter value can never widen collection (I-SERVER-8, ETHICS "Window titles"); fixed query count per policy fetch (approved by owner 2026-11-17, docs/plan/server-implementation.md M3) |
| 27 | **Ingest schema**: every event type has its own validator with a field allow-list and type and length limits (heartbeat strings, `description`, `subject`). Fields outside the allow-list are dropped, never stored. Titles the effective `title_capture` (#26) does not allow are dropped on the server too. The allow-lists come from docs/PROTOCOL.md | the agent is not trusted to filter for us; unknown fields cannot smuggle data the ethics table does not allow (I-SERVER-16, I-SERVER-25; approved by owner 2026-11-17, M4) |
| 28 | **Enrollment token**: staff create a one-time per-PC token on the authenticated `/enroll` page (stored hashed). `register` with a valid unused token auto-approves; with only the lab key the PC stays pending until a staff click. MAC auto-approve (F16) is removed. `machine_uid` is required; an existing PC is adopted only by `machine_uid` or an explicit staff choice, conflicts are flagged and never merged. Rotating the lab key also invalidates unused tokens. The CSR flow is unchanged | a MAC is spoofable and the lab key is shared, so neither alone may yield a cert without a human (I-SERVER-4, I-SERVER-5; approved by owner 2026-11-17, M2) |
| 29 | **Append-only alert reviews and audit chain**: acknowledging an alert appends an `alert_reviews` row (who, when, note) and never edits or deletes one; already-acknowledged alerts are skipped and batch IDs are scoped to the lab. Each `audit_log` row stores `prev_hash` = SHA-256 of the previous row's hash and its own canonical content; `xg:audit-verify` checks the chain. If `Audit::log` fails, the action fails. Exemption changes are logged as changed, without the reason text | every flag stays traceable to a human review; tampering with the audit log becomes detectable (I-SERVER-13, I-SERVER-14; approved by owner 2026-11-17, M5) |
| 30 | **One research export, on the server**: `App\Services\ResearchExport` (F52) is the only research export; the analysis CLI `xg_analysis export` is removed. CSV only; Parquet is made from the CSV by the researcher | the CLI read the DB directly, so it bypassed the role check and wrote no audit row; an audit row from Python would need a second copy of the hash chain (#29); its columns and consent rule had drifted from the server's (I-ANALYSIS-22; approved by owner 2026-11-17, docs/plan/analysis.md Step 13) |

# Audit: xephyguard-screen/ + embedded streamer agent/apps/screen_streamer.cpp (read-only review, 2026-11-17; nothing built or run)

Scope: features F43 (live view), F45 (gateway relay), F47 (standalone agent), and the embedded streamer F95. Everything below is from reading code. **Performance rows are derived from code constants and are not measured**; the plan starts by measuring (see docs/plan/screen.md). Cross-component findings already in other audits are listed at the end, not repeated.

## Smoothness target (proposal, needs owner approval)
Reference: Veyon-style behaviour (from memory, not re-checked): a monitoring wall of small thumbnails refreshed about once a second, and a single-PC view that feels like remote desktop (roughly 10-30 fps on a LAN). Proposed XephyGuard targets:

| Mode | Target | Current (from code) |
|---|---|---|
| Wall (all PCs) | 320x180 thumbnail, ~1 update/s per PC, <10 KB each, no more than one stream per PC and no full-res stream | Wall mode exists in the state machine (5 s, full keyframe each) but the embedded streamer always starts `live` (I-SCREEN-7) |
| Single PC live | p95 >= 15 fps while content changes, glass-to-glass latency < 250 ms on LAN, first picture < 1 s | Hard ceiling 5 fps (I-SCREEN-8), ack-gated, serial tile decode (I-SCREEN-9) |
| Student PC cost | 0 % CPU idle, < 10 % of one core while streaming a 1080p desktop | Unknown; full-frame copy + hash every cycle (I-SCREEN-11) |
| Recovery | Reconnect in < 3 s without staff clicking | No auto-reconnect, single-use token (I-SCREEN-17) |

## Findings

| ID | Severity | File:line | Problem | Fix |
|---|---|---|---|---|
| I-SCREEN-1 | Critical | gateway/auth.go:130 (+ gateway/main.go:73-79) | `AuthAgent` accepts the client-supplied header `X-Agent-Cert-Fingerprint` as proof of identity when no TLS client cert is present, and nothing checks that fingerprint against a registered PC. Anyone who can reach :8082 can publish frames for any `stream_id` (fake another PC's screen, inject content to viewers). | Remove header trust. Authenticate agents only by a per-PC JWT minted by the CCC (bound to `pc_id` + `stream_id`), or by an nginx-verified header that the gateway accepts only from loopback. |
| I-SCREEN-2 | High | gateway/relay.go:259-266 (+ :171-176) | The stream an agent writes to is taken from the `stream_id` query and then from every frame header (`frameStreamID`), so an authenticated agent can switch mid-connection to any other stream and overwrite it. | Bind the connection to one stream at auth time; drop frames whose header `stream_id` differs. |
| I-SCREEN-3 | High | gateway/relay.go:322-329 (+ auth.go:111-119) | Viewer auth runs only at connect. A viewer keeps streaming after the 30 s lease ends, after `stop`, after the instructor logs out or the session ends (the server only closes the `screen_view_audits` row; the gateway is never told). | Add a revoke path (CCC calls the gateway, or the gateway re-checks a lease every 30 s) and close viewer sockets on lease expiry. |
| I-SCREEN-4 | High | capture/x11_capture.cpp:43-44 | The shared-memory segment is created `IPC_CREAT \| 0777`, so any local user can attach it and read the student's screen pixels. | Create with mode 0600 (owner only); better, use `XGetImage`/MIT-SHM with a private segment and `shmctl(IPC_RMID)` right after attach. |
| I-SCREEN-5 | High | agent/apps/screen_streamer.cpp:211,294 (+ agent/agent_state.cpp:218) | The embedded streamer never calls `set_privacy_filter`/`set_privacy_checker`, so the mask (password managers, banking, private windows) is never active even though F43 describes it. | Wire `PrivacyFilter` with a window provider from the helper, rules from policy, fail-safe mask on error. |
| I-SCREEN-6 | High | gateway/auth.go:122-125 | When the token has no `stream_id`, the stream becomes `student_id`. Stream ids are PC ids elsewhere, so a student id can equal another PC's stream id and route a viewer to the wrong screen. | Require `stream_id` in the token and reject 0. |
| I-SCREEN-7 | High | agent/apps/screen_streamer.cpp:244,318 | The streamer always calls `on_view_start(stream_id, "live")`; the `mode` in the CCC token (`wall`, `snapshot`) is ignored by both gateway and agent. A wall of N PCs therefore opens N full-resolution live streams. | Carry `mode` from the CCC to the agent (signed), honour `wall` (thumbnail, 1 fps) and `snapshot`; gateway enforces the token's mode. |
| I-SCREEN-8 | High | core/flow.cpp:55-60 (+ flow.cpp:19-26) | `target_interval = clamp(2*RTT, 200, 1000)` ms, and at most 3 frames in flight, so live view cannot exceed 5 fps even on a fast LAN. Frames are only sent after the viewer has acked the previous one, so one slow decode slows everything. | Pace by capture rate and measured bandwidth (target 15-30 fps), keep an in-flight window of bytes not frames, and skip (coalesce) updates instead of waiting. |
| I-SCREEN-9 | High | viewer/viewer.js:242-254, 307-343 | `onmessage` is `async` and awaits `createImageBitmap` one tile at a time. Messages overlap, so frame N+1 can finish and draw before frame N: stale tiles overwrite newer ones. `lastAppliedSeq` is advanced before the awaits. A 500-tile keyframe is 500 serial awaits; the ACK is sent only after all of them. | Put frames in an ordered queue; decode tiles in parallel (`Promise.all`) or off-thread (worker, `OffscreenCanvas`); drop frames when behind; ACK on receive, not on paint. |
| I-SCREEN-10 | High | core/encoder.cpp:64,100 (+ :86) | Each 64x64 tile is encoded by its own WebP/JPEG call with its own allocation, single-threaded, per capture. Small tiles compress poorly (container overhead) and blur text (4:2:0). A 1080p keyframe is about 510 encode calls. Not measured. | Merge dirty tiles into larger rectangles; reuse encoder state; encode on a worker pool; add a lossless/high-quality path for text; measure ms per frame first. |
| I-SCREEN-11 | Medium | capture/x11_capture.cpp:65,98-137 | XDamage is created but never read; every cycle does a full `XShmGetImage`, copies the whole frame and sets alpha pixel by pixel, then hashes every tile (`full_dirty=true`). Wasted CPU on the student PC. Not measured. | Consume Damage events for dirty rects; avoid the per-pixel alpha loop (encode as BGRX or fix alpha in the encoder); skip capture when no damage. |
| I-SCREEN-12 | Medium | core/flow.cpp:73-77 (+ agent_state.cpp:198-203, gateway/relay.go:296-301) | Any viewer `KEYFRAME_REQ` resets the sender and forces every tile; a slow viewer's queue overflow makes the gateway send another request each time. Two viewers cause keyframe storms and large bursts. | Per-viewer catch-up (send a keyframe only to that viewer from the cached copy), rate-limit requests to one per second. |
| I-SCREEN-13 | Medium | gateway/relay.go:459-469 (+ :183, :383) | Any binary message of 28+ bytes from a viewer is forwarded to the agent unchecked, up to the 16 MB read limit, including `Frame`, `Cursor` or `Status` types. | Allow only `Ack` and `KeyframeReq`, exactly 28 bytes, stream id rewritten by the gateway; read limit 4 KB for viewers. |
| I-SCREEN-14 | Medium | gateway/main.go:111-118 (+ relay.go) | `http.Server` has no timeouts and no WebSocket ping/pong. A pulled cable or crashed helper leaves a half-open agent socket; viewers see a frozen picture and the dashboard shows "live". | Set `ReadHeaderTimeout`; ping every 10 s, close after 2 missed pongs; send the "agent offline" status. |
| I-SCREEN-15 | Medium | gateway/relay.go:178-180, 368-370 | `InsecureSkipVerify: true` disables the WebSocket Origin check, so any web page can open a viewer socket if it holds a token (cross-site WebSocket hijacking). | Check Origin against the dashboard origin(s) from config. |
| I-SCREEN-16 | Medium | gateway/relay.go:274-279, 353-358 | The last keyframe is cached for the life of the agent connection and replayed to every new viewer, even when the agent is now masked, secure-desktop or idle. A viewer can see an old screen as if it were live (privacy and correctness). | Cache for at most a few seconds, never across a MASKED/SECURE flag, and mark replayed frames as "cached". |
| I-SCREEN-17 | Medium | gateway/auth.go:111-119 (+ viewer/viewer.js:234-236) | The viewer token is single-use (`jti`) and `ScreenViewer` has no reconnect. After any network blip the picture stops until staff click again; the lease-renew token cannot be reused by the same page. | Auto-reconnect with backoff using a freshly issued token (page asks the CCC); keep the old stream cached for a short grace period. |
| I-SCREEN-18 | Medium | agent/apps/screen_streamer.cpp:92-138, 205-217 | On Windows, the capture thread (`send_binary`/`reconnect` from the sender lambda) and the receive thread (`close`/`reconnect`) both touch the WinHTTP handles without a lock; close can run while a send is in progress. | One mutex around the client, or a single I/O thread that owns the socket. |
| I-SCREEN-19 | Medium | gateway/relay.go:217,263-265 | `stream` is assigned in the reader loop and read in the writer goroutine with no synchronisation (data race); the writer polls every 50 ms until `stream` is set. | Resolve the stream once before starting the writer, or guard with an atomic pointer. |
| I-SCREEN-20 | Medium | agent/apps/screen_streamer.cpp:235-247, 309-321 | The helper starts capturing as soon as the gateway sends any `KeyframeReq` or `Status` with viewers > 0. There is no CCC-signed start command, no lease and no maximum duration on the agent side. | The service (not the gateway) tells the helper to start, with an expiry; the helper stops itself when the lease lapses. |
| I-SCREEN-21 | Medium | core/protocol.h:14 (+ core/protocol.cpp:107) | `kMaxTiles = 4096` rejects any frame wider than about 4096 x 4096 px worth of tiles. A multi-monitor X11 root (for example 2 x 4K) fails to encode or decode and shows nothing. | Raise the limit with a per-message tile cap and send per-monitor frames (`monitor_id` is always 0 today). |
| I-SCREEN-22 | Medium | core/encoder.cpp:21 (+ capture/win_dxgi_capture.cpp:24-40) | Only one output is captured on Windows and `monitor_id` is always 0, so a second monitor is invisible (Veyon shows all). | Capture each output; send per-monitor frames; viewer shows a monitor selector. |
| I-SCREEN-23 | Medium | agent (cursor): agent/agent_state.cpp:162 (+ viewer/viewer.js:264) | `send_cursor` is never called by the embedded streamer and the viewer ignores `Cursor` messages, so the remote pointer is never shown. | Send cursor position at up to 30 Hz as its own small message and draw it on a separate overlay canvas. |
| I-SCREEN-24 | Medium | gateway/auth.go:24-29, 88-126 | The `mode` and `lab_session_id` claims are parsed but never used. A `snapshot` or `wall` token opens a live stream, and the token is not tied to a running lab session. | Return a struct (stream, mode, lease expiry) from `AuthViewer` and enforce it. |
| I-SCREEN-25 | Medium | gateway/relay.go:487-505 (+ agent streamer) | No metrics: no per-stream fps, bytes, queue drops, keyframe requests, RTT. Smoothness cannot be shown or regressed. | Add `/metrics` (text format, no new dependency) and a debug stats message in the viewer. |
| I-SCREEN-26 | Low | gateway/relay.go:98-105 | `removeStream` is never called, so every `stream_id` ever used stays in the map for the life of the process. | Remove a stream when it has no agent and no viewers for 60 s. |
| I-SCREEN-27 | Low | viewer/tilecanvas.js:52,72 (+ viewer/viewer.js:322-329) | `push(...tiles)` and `shift()` in a loop are O(n^2) for big frames; the Raw codec converts pixels in a JS loop. | Use an index loop and a swap buffer; use `ImageData` from a typed-array view. |
| I-SCREEN-28 | Low | viewer/viewer.js:199-207, 250, 340 | The constructor overloads on `arguments[2]`, and `catch {}` silently swallows all control and tile decode errors. | Single options object; count and report decode errors via `onError`. |
| I-SCREEN-29 | Low | gateway/auth.go:97 (viewer URL `?token=`) | The token is in the URL query, so nginx access logs and browser history keep it (single-use and 30 s, so impact is small). | Send the token as the first WebSocket message or `Sec-WebSocket-Protocol`. |
| I-SCREEN-30 | Low | agent/apps/screen_streamer.cpp:103-118 | The Windows receive buffer is 4096 bytes; a larger or fragmented message is treated as complete. | Loop until `final` fragment, cap total size. |
| I-SCREEN-31 | Low | gateway/gateway.exe (tracked), .gitignore | A stale binary `gateway.exe` (about 37,000 lines in `wc`) is tracked in git. | Remove from git and ignore `*.exe`. |
| I-SCREEN-32 | Low | gateway/go.mod:5-8, .github/workflows/ci.yml | Dependencies are marked `// indirect` (`go mod tidy` never run); Go tests, `go vet` and the `xgtests` suite are not run in CI (CI only compile-checks agent includes). | `go mod tidy`; run `go vet`, `go test -race` and `xgtests` in CI (CI edit needs approval). |
| I-SCREEN-33 | Low | CMakeLists.txt:44-84 | libwebp and libjpeg-turbo are fetched at configure time by tag (not commit hash) and CMake files are patched on the fly. | Pin by commit hash; vendor or document the patch. |
| I-SCREEN-34 | High | agent/agent_state.cpp:239,248,282,371 (xephyguard-screen) (+ agent/apps/screen_streamer.cpp:262-263,303,327-330) | The capture loop polls with `sleep_for` 10/20/30/50 ms, so a viewed PC wakes 30-100 times a second even when nothing changes. The streamer's main loop (100 ms), receive loop (250 ms) and reconnect timers also wake 15+ times a second while nobody is viewing. On laptops and integrated-GPU PCs this keeps the CPU out of deep sleep (power) for no benefit. Not measured. | Block on events: poll the X11 Damage fd, `DXGI AcquireNextFrame(timeout)`, a condition variable for start/stop, and a blocking socket read; idle target under 2 wake-ups per second. |
| I-SCREEN-35 | High | capture/win_dxgi_capture.cpp:24-40,197-216 (+ capture/win_gdi_capture.cpp) | On Windows the whole desktop is mapped and copied row by row to system memory for every frame even when only small rectangles changed (dirty rects are read but only used for hashing), and the fallback is GDI `BitBlt`, which is CPU-heavy. Hybrid (integrated + discrete GPU) laptops can also pick the wrong adapter. Not measured. | Copy only dirty/move rectangles from the GPU staging texture, keep a persistent shadow frame, capture on the adapter that owns the output, and force a low fps cap when only GDI is available. |
| I-SCREEN-36 | Medium | agent/agent_state.cpp:206-373, core/encoder.cpp (no budget anywhere) | There is no CPU budget or self-throttle. On a slow CPU or software-rendered desktop the streamer takes as much CPU as it needs, competing with the student's work (exam performance, fan noise, battery). Threads run at normal priority. | Add a governor that measures its own thread CPU time and lowers fps, quality and rectangle size to stay under a budget (default 8 % of one core); run capture/encode threads at idle/below-normal priority. |

## Cross-references (already in other audits; fix there)
- Plaintext `ws://` + token on :8082, `screen_tls=false` default: I-AGENT-1, I-CCC-1, I-CCC-7.
- Shared gateway secret sent to every agent and to helpers: I-AGENT-6, I-SERVER-11.
- Client `stream_id` accepted by the token endpoint, idle PCs viewable by any account, no audit on evidence: I-SERVER-1, I-SERVER-3, I-SERVER-10.
- Student notice says nothing is recorded while screens are viewed: I-AGENT-21, I-SERVER-12.
- Wayland sessions cannot be captured (`agent/platform/.../capabilities`, agent.cpp:1138); on Ubuntu this is the default session. Fix is a deployment choice (force Xorg for lab PCs) or a PipeWire portal path that needs a user prompt; decide with the owner. Not scored here.

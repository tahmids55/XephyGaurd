| ID | Severity | File:line | Problem | Fix |

| I-AGENT-1 | Critical | agent/core/include/xg/config.hpp:16 | Screen stream defaults to `screen_tls=false` on :8082, so the helper sends full screen content and `X-Agent-Token` over plaintext WebSocket with no mTLS (screen_streamer.cpp:289, helper_main.cpp:543). This breaks the TLS 1.3 + mTLS invariant and puts screen content on the LAN in clear. | Make TLS mandatory for the screen path (refuse to connect without it), use client-cert auth, and drop the plaintext branch in WebSocketClient for this caller. |
| I-AGENT-2 | Critical | agent/core/src/config.cpp:119 | Restrictive mode (`chmod 0600`) is applied on POSIX only. On Windows, agent.toml (bearer token, screen token) and agent.key (crypto.cpp:145) inherit the ProgramData ACL, and the installer grants Users RX there. The helper even reads agent.toml as the student (helper_main.cpp:471), so any student can steal the PC's mTLS key and token. | Set an explicit SYSTEM/Administrators-only DACL when writing config and key on Windows, and stop the helper reading agent.toml (use IPC config only). |
| I-AGENT-3 | High | agent/core/src/enroll.cpp:55 | With discovery and no `--ca-fingerprint`, the fingerprint comes from the unauthenticated UDP reply (discovery.cpp:26-29). A rogue LAN host can answer first and the PC enrolls to it without `--trust-on-first-use`. | Never take the fingerprint from a discovery reply. Require `--ca-fingerprint` or explicit TOFU when discovery is used. |
| I-AGENT-4 | High | agent/core/src/http.cpp:54 | Chunk size is not bounds-checked: `pos + len + 2` wraps on a huge hex length, so `pos` can rewind. Any local user's server on a probed port (agent.cpp:345) can loop the root agent's parser forever while `body` grows until OOM. | Reject chunk sizes larger than the remaining buffer or a fixed cap before adding; use overflow-safe comparisons. |
| I-AGENT-5 | High | agent/platform/windows/ipc_pipe_win.cpp:94 | The pipe DACL gives Authenticated Users GENERIC_WRITE (which includes FILE_CREATE_PIPE_INSTANCE), and there is no FILE_FLAG_FIRST_PIPE_INSTANCE. A student can create a squatting server instance. The helper never checks the server's identity, so it accepts forged `config` (e.g. collect=false). | Grant AU only FILE_GENERIC_READ\|FILE_WRITE_DATA, create the first instance with FILE_FLAG_FIRST_PIPE_INSTANCE, and have the helper check GetNamedPipeServerProcessId belongs to SYSTEM. |
| I-AGENT-6 | High | agent/core/src/agent.cpp:880 | The screen-gateway `agent_token` is broadcast to user-level helpers, so every logged-in student can read it (from own helper memory or an LD_PRELOADed helper that passes the exe check in ipc_unix.cpp:139). | I-AGENT-7 | High | agent/core/src/agent.cpp:1446 | `rescan`/`kill` commands run scans on the realtime thread (and `apply_policy` clears `next_run_` from the uplink thread at line 97).
